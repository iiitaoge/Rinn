  2. EventBus 草案（不是 Component，是全局单例）

  namespace Rinn::Events {
      enum class Category : uint8_t { Material, Information, Social, Internal };

      struct Event {
          Category category;
          uint16_t tag;        // TaxRaised / Insulted / Gift / ...
          Entity source;
          Entity target;
          float magnitude;
          uint32_t tick;
      };

      class EventBus {
          std::array<Event, 1024> ring;
          uint16_t head = 0, tail = 0;
      public:
          void publish(const Event& e);
          template<typename Fn> void drain(Fn&& fn);
      };
  }

  Event 本身 trivially copyable。EventBus 是单例，不进 ECS。

  最大的那道坎是 M3：事件驱动

  之前你写的 System 都是"每帧扫 pool，按当前状态更新"——纯
  reactive。事件驱动要求你换一种问法：

  - 这件事何时发生？
  - 谁关心？
  - 处理顺序有没有依赖？
  - 这一帧的 event 是不是要下一帧才被消费？

  这套思维和渲染完全没关系。第一次写 EventBus 你会反复改设计 2-3 
  次——别把这当失败信号，是必经过程。挺过 M3，后面 M4-M6 会重新顺手。

  真正的差距：debugging 基础设施

  时根本不知道发生了什么，调试时间会指数级膨胀。
