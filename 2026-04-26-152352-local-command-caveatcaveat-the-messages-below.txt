  下面给你一套完整工作流。

  总策略：markdown 永远是源，docx 是最后一步生成的产物

  把整本论文继续当作"代码项目"对待：

  - 新功能写完 → 写新的 08_editor.md / 09_ai.md
  这样的章节文件，按数字前缀排序自动入位（08/09 插在 HD-2D
  之后、性能测试之前，正好是大纲里预留的位置，前面章节号不动）
  - 章节顺序由文件名前缀决定，不在文件里写"第 X 章"硬编号——pandoc 的
  --number-sections 会自动按 # 层级编号

  工具链推荐：Pandoc + reference.docx

  Pandoc 能做的事：标题层级、正文、列表、表格、代码块、目录、章节自动编号。
  Pandoc 做不了的事：插图（要 Word 里手插）、复杂公式排版、参考文献 GB/T 7714
  微调、封面、扉页签字栏。

  最关键的一招是 --reference-doc=template.docx：你提前在 Word
  里做一个"样式模板"文件，pandoc 转换时自动把模板里的样式套到新生成的 docx
  上。改一次模板，每次重新生成都自动套用。

  第二步：建一个一键生成脚本

  放到 docs/thesis/build.sh（或 .ps1 / .bat），大致结构：

  #!/usr/bin/env bash
  cd "$(dirname "$0")"

  # 1. 按文件名顺序合并所有 markdown（abstract 先，附录致谢最后）
  cat abstract.md \
      [0-9][0-9]_*.md \
      references.md \
      appendix.md \
      acknowledgments.md \
      > _full.md

  # 2. 一键生成 docx
  pandoc _full.md -o Project_Rinn_thesis.docx \
      --reference-doc=template.docx \
      --toc --toc-depth=3 \
      --number-sections \
      --from=markdown+raw_html \
      --to=docx
