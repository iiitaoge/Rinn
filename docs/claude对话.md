  还有一个关键决策（这才是工程问题）：

  TBN 矩阵谁来算、什么时候算、传不传？

  我们项目里 quad 朝向只有有限的几种（地面 / 立式 / 也许将来斜坡）。所以 TBN 矩阵其实只有几种固定值。

  你有两个方案：
  - (A) C++ 端算好 TBN 矩阵，每个 pass 上传 uniform mat3（类似现在的 facenormal 做法）
  - (B) shader 里只接收 facenormal，用 if-else 判断"如果 facenormal 朝 Y 就 swizzle xzy，朝 Z 就不变"

  哪种更好？为什么？（提示：D1 延迟抽象 vs D3 状态切换。看你 log 顶上的设计原则。）
