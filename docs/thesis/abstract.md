# 摘要

近年来，独立游戏开发者与中小团队对自主可控、轻量易扩展的游戏引擎需求日益增长，与此同时，以《八方旅人》系列为代表的 HD-2D 风格因其兼具像素美学与现代后处理特性，受到玩家与从业者的广泛关注。本课题面向上述需求，以"自下而上"的方式设计并实现了一款基于实体-组件-系统（Entity-Component-System，ECS）架构的轻量级游戏引擎 Project Rinn，并在其上进行了 HD-2D 渲染风格的原理验证。

引擎以 C++20 与 raylib 5.5 为基础，自主实现了 ECS 核心：以 32 位整数承载实体句柄并通过版本号防御 ABA 问题，使用 SparseSet 作为组件存储以兼顾 O(1) 增删与稠密遍历，借助模板特化为每种组件类型在编译期分配唯一标识，并通过"最小池驱动"的 View 实现多组件交集查询。在子系统层面，分别实现了三维相机下的精灵渲染、纯位置积分的物理、空间哈希加 AABB 的二阶段碰撞、调试 UI 与单 BGM 流的音频。脚本层基于 Lua 与 sol2 实现 C++↔Lua 双向调用，结合 Tiled 编辑器导出的地图数据驱动场景构造，并以纯 Lua 表声明对话分支与全局 flag。HD-2D 渲染通过区分立式精灵与地面瓦片的法线、在片段着色器中以朗伯模型计算光照，得到了"一明一暗"的体积感初步效果。在 NPC AI 层面，设计并实现了一套基于需求-情绪-决策-执行管线的自主 NPC 系统：NeedComponent 与 EmotionComponent 承载角色的动机与情绪状态；发布-订阅式 EventBus 以确定性 FIFO 传递世界事件；AppraisalSystem 将事件映射为主观化的情绪 delta 并通过 KnowledgeFactComponent 的 bitset 实现 NPC 之间的信息差；DecisionSystem 以 Utility AI 公式（效用 = 增益 × 需求紧迫度 × 情绪调制因子）自主选择最优行动；ActionExecutionSystem 在动作完成后发布新事件并触发涌现叙事循环；LineSystem 以"立场一致性"过滤机制将内部状态映射为与人格相符的可见台词。四个 NPC 角色的端到端场景验证了上述管线在"加税令"剧情触发下的自发群体行为与信息不对称响应。性能方面，借助手写的 cache miss 实测、false sharing 对照实验与覆盖 ECS 核心的 70 余个 GoogleTest 用例，验证了数据布局选择的有效性与系统行为的确定性。

论文最后总结了已完成的工作，分析了命名空间级全局变量、Lua 字符串调度等遗留问题，并将 HD-2D 后处理与可视化编辑器列入分级展望，为后续工作预留了可扩展的章节结构。

**关键词**：游戏引擎；实体-组件-系统；HD-2D；NPC AI；Utility AI；缓存局部性；Lua 嵌入式脚本

# Abstract

In recent years, independent game developers and small teams have shown growing demand for lightweight, extensible game engines under their own control. At the same time, the HD-2D visual style—popularized by titles such as *Octopath Traveler*—has attracted wide attention for combining pixel-art aesthetics with modern post-processing. Motivated by these trends, this work presents *Project Rinn*, a lightweight game engine designed and implemented from the ground up around the Entity-Component-System (ECS) architecture, on top of which a prototype of HD-2D rendering is validated.

Built on C++20 and raylib 5.5, the engine implements the ECS core from scratch: entity handles are packed into a single 32-bit integer with an embedded generation counter to defend against the ABA problem; component storage uses a SparseSet to achieve O(1) insertion/deletion alongside cache-friendly dense iteration; a unique component identifier is assigned per type at compile time via template specialization; multi-component intersection queries are realized through a "smallest-pool-driven" View. At the subsystem level, the engine provides sprite rendering under a 3D camera, a minimal position-integration physics step, two-phase collision detection combining a spatial hash with axis-aligned bounding boxes, a debug UI, and a single-BGM audio module. The scripting layer integrates Lua via sol2 to enable bidirectional calls between C++ and Lua; scenes are constructed from maps exported by the Tiled editor, while dialogues and progression are declared entirely as Lua data with global flags. For HD-2D rendering, upright sprites and ground tiles are differentiated by their face normals, and Lambertian shading in the fragment shader produces a preliminary sense of volumetric lighting. The NPC AI pipeline, developed across six milestones, provides autonomous NPC behavior without scripted if-else: *NeedComponent* and *EmotionComponent* model motivation and emotional state; a deterministic publish-subscribe *EventBus* propagates world events; *AppraisalSystem* maps events to subjective emotion deltas and tracks per-NPC information asymmetry via a bitset-based *KnowledgeFactComponent*; *DecisionSystem* selects actions via a Utility AI formula (utility = gain × need-salience × emotion-modulator); *ActionExecutionSystem* completes actions, publishes follow-on events, and drives emergent narrative loops; *LineSystem* applies an agency-aware consistency filter to produce character-coherent dialogue. An end-to-end scenario with four NPCs validates spontaneous group behavior and information-asymmetric responses under a tax-increase trigger. To validate the chosen data layout, a hand-written cache-miss benchmark, a controlled false-sharing experiment, and over seventy GoogleTest cases covering the ECS core demonstrate the effectiveness and determinism of the implementation.

The thesis concludes by summarizing the work delivered, analyzing remaining issues such as namespace-level global state and string-based Lua dispatch, and outlining future work in two tiers—HD-2D post-processing and a visual editor—within a chapter structure that has been deliberately reserved for these extensions.

**Keywords**: Game Engine; Entity-Component-System; HD-2D; NPC AI; Utility AI; Cache Locality; Embedded Lua Scripting
