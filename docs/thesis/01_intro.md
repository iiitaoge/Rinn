# 第 1 章 绪论

## 1.1 课题研究背景与意义

电子游戏作为综合性极强的数字内容产品，其制作过程涉及程序、美术、设计、音频等多个工种的紧密协同。在这一协同链条中，**游戏引擎**承担着将各类资源、规则与运行时行为整合为可执行体验的中枢职责。商业引擎如 Unreal、Unity 长期占据市场主流，凭借完整的功能、成熟的工具链与广泛的社区生态，覆盖了从 AAA 大作到独立游戏的大部分项目类型。然而，对于以学习引擎机制为目的的研究者、追求轻量可控的独立开发者，以及希望在特定品类上做出差异化的中小团队而言，全功能商业引擎的"重"既是优势也是负担：庞大的源码量与复杂的子系统耦合使得学习曲线陡峭；不透明的渲染管线与抽象层叠加让性能调优变得困难；许可证模型与版本绑定带来的中长期成本也并非每个团队都能承受。在此背景下，自研轻量级游戏引擎重新成为学术与工程界共同关注的方向。

与此同时，2D 游戏的视觉表达正在经历一次"风格回潮"。Square Enix 于 2018 年发布的《八方旅人》（*Octopath Traveler*）首次提出"HD-2D"概念，并在续作以及《三角策略》《勇气默示录 II》等作品中持续完善。HD-2D 的核心特征是：以传统像素美术绘制角色与瓦片，再放入透视相机下的三维场景，叠加 bloom、tilt-shift 景深、体积光等现代后处理，使复古的像素角色获得"立在世界里"的体积感与电影感。这一风格在玩家与从业者中获得广泛认可，技术上则要求引擎同时具备 2D 像素管线与 3D 场景能力，并提供细粒度的渲染控制，正是商业引擎"开箱即用"模式不擅长的应用场景。

数据驱动的实体-组件-系统（Entity-Component-System，简称 ECS）架构是上述背景下另一项关键技术演进。传统面向对象（OOP）的继承层级在游戏对象体系中常常引发"菱形继承"与"组件膨胀"，并导致内存布局碎片化、缓存失效频繁。ECS 通过将"是什么"（组件数据）与"怎么做"（系统行为）解耦，把同类组件聚集在连续内存中，从而显著改善 CPU 缓存命中率。Unity 推出的 DOTS、Bevy 引擎、EnTT、Flecs 等开源库的相继成熟，使 ECS 从理论走向工业实践，亦成为新一代自研引擎的事实标准。

本课题立足于上述三条线索的交汇点：一方面，以"自下而上"的方式实现一款基于 ECS 架构的轻量级游戏引擎 Project Rinn，作为独立开发与教学研究的样本；另一方面，在引擎之上完成 HD-2D 风格的渲染原理验证，为后续完善具备 HD-2D 能力的小型作品奠定基础。课题的意义可概括为如下三点：

1. **教学与学习价值**：完整暴露 Entity 句柄、SparseSet、Component 类型 ID、View 等 ECS 核心机制的实现细节，配合可执行的性能基准与单元测试，为研究者提供一个"可拆解、可读懂、可调优"的引擎样本。
2. **工程与可扩展性价值**：在保持代码量可控的前提下，提供数据驱动的关卡构造、可嵌入的 Lua 脚本、以及预留的渲染、编辑器、AI 等扩展接口，便于在毕业设计周期之外继续演化为更完整的产品级原型。
3. **品类与风格价值**：以 HD-2D 作为渲染风格目标，验证其核心技术点（精灵法线、3D 场景、光照分层）在自研引擎中的可行性，为同类小型项目提供参考实现。

## 1.2 国内外研究与实践现状

围绕本课题涉及的几条技术主线，国内外已有较为丰富的研究与实践积累。

**通用商业引擎的架构演进**方面，Epic Games 的 Unreal Engine 自 4 代起将渲染管线全面切换为基于物理的着色（PBR），并在 5 代中引入 Nanite 微多边形几何与 Lumen 实时全局光照，将"近乎电影级"的视觉表达带入实时渲染领域；Unity 则在保持组件式编辑器易用性的同时，于 2018 年推出 Data-Oriented Technology Stack（DOTS），通过 Burst 编译器、Job System 与 ECS 三件套，将面向数据设计纳入主流工作流。Godot 引擎以 MIT 许可证与场景树（Scene Tree）+ 节点（Node）的组合范式，在独立开发圈层内迅速积累用户。这些主流引擎的共同趋势是：渲染上拥抱 PBR 与延迟着色，运行时上吸纳 ECS 与多线程友好的数据布局，工具链上提供可视化编辑与脚本绑定的双轨道。

**ECS 框架与面向数据设计**方面，C++ 生态中的 EnTT 由 Skypjack 开发并维护，是当前最具影响力的开源 ECS 库之一，其 sparse set + 视图（view）模型直接启发了大量自研实现。Rust 生态中的 Bevy 以"插件化"的 ECS 调度器构建整套引擎；Flecs 强调跨语言绑定与可视化检视；Mike Acton 在 GDC 2014 的演讲 *Data-Oriented Design and C++* 系统阐述了"理解硬件，关注数据流"的设计哲学，被广泛视为面向数据设计的入门必读。Bitsquid（即后来的 Stingray）团队的早期博客对 ID 化资源、关系数据库式实体表的讨论，亦被许多自研引擎引用。学术层面，Adams 等关于 cache-aware 数据结构的研究，以及 Drepper 的经典综述 *What Every Programmer Should Know About Memory*，则提供了从硬件视角理解性能的理论框架。

**HD-2D 风格与渲染**方面，Square Enix 在 GDC 与 CEDEC 的多次公开分享中，介绍了 HD-2D 在《八方旅人 2》中的具体实现路径：以正交投影外观下的透视相机让 2D 精灵获得空间感、对像素精灵手绘或自动生成法线贴图以参与光照、使用屏幕空间 bloom 与 tilt-shift 模糊营造缩微景深、对场景中关键物件叠加体积光等。学术界在 *SIGGRAPH* 与 *I3D* 等会议上对 stylized rendering、normal-mapped 2D sprites 等子主题持续有论文发表。开源圈层中，Godot、Unity 社区均出现了大量"HD-2D-like"的实践教程与插件，但完整、自由开放、面向自研引擎的参考实现仍较为稀缺。

**嵌入式脚本语言**方面，Lua 自 1993 年由 PUC-Rio 的 Roberto Ierusalimschy 等人开发以来，凭借极小的解释器体积、清晰的 C API 与极宽松的 MIT 许可证，成为游戏行业的事实标准嵌入式脚本语言，被《魔兽世界》客户端、《原神》早期版本、Roblox 客户端等广泛采用。C++ 与 Lua 之间的绑定库经历了从 LuaBind、tolua++ 到 sol2 的演进，sol2 利用 C++17 的模板元编程能力极大简化了双向绑定代码，是目前社区接受度最高的方案之一。

**国内研究与实践**方面，伴随《原神》《明日方舟》《崩坏：星穹铁道》等高质量国产游戏的出现，国内大型厂商如米哈游、网易、腾讯均建立了自研或深度定制的引擎团队，并在公开演讲中分享过相关经验。高校与开源社区方面，国产 ECS 库 sakura、cgmath 风格的数学库等不断涌现；中文技术社区 ECS 主题下的博客、知乎专栏、B 站讲解视频也在过去数年间形成了较为完整的学习资源体系。然而，将 ECS、HD-2D、Lua 脚本系统在同一个轻量级原型中完整串联起来、并以可读性与可教学性为优先目标的开源工作仍然较少，这正是本课题的切入点之一。

## 1.3 主要研究内容与目标

围绕"基于 ECS 架构的 HD-2D 游戏引擎"这一总目标，本课题的研究内容可拆解为以下五个方面。

**一、ECS 核心的设计与实现**。从最基础的实体句柄入手，设计一种 32 位、含版本号的 Entity 数据类型以防御 ABA 问题；以环形缓冲区实现实体索引的 FIFO 复用，使版本号自然递增；以 SparseSet 作为通用组件存储结构，兼顾 O(1) 增删与稠密线性遍历；通过模板特化与原子计数器为每种组件类型在编译期分配唯一的 8 位 ID；在此基础之上构建统一的 Registry 接口，并提供基于"最小池驱动"的 View 模板支持任意数量组件的交集查询。

**二、子系统的实现与集成**。在 ECS 之上集成游戏引擎所必需的最小子系统集合，包括：基于 raylib + rlgl 的渲染系统（含三维相机、精灵 3D 化绘制、中文字体支持、对话气泡）、纯位置积分的物理系统、空间哈希加 AABB 的二阶段碰撞检测系统、薄封装的输入系统、单 BGM 流的音频系统，以及基于 Dear ImGui 的调试 UI。

**三、Lua 脚本子系统与数据驱动场景**。基于 sol2 实现 C++ 与 Lua 的双向绑定，将组件挂载、移除、查询、输入读取、相机控制等操作开放给脚本端；引入 Tiled 编辑器作为关卡设计工具，编写解析其 Lua 导出格式的加载器，将图块层与对象层映射到 ECS 实体；以纯 Lua 表声明对话分支与全局 flag，实现引擎不感知具体业务的通用剧情推进逻辑。

**四、HD-2D 渲染风格的原理验证**。通过区分立式精灵与地面瓦片的几何朝向并赋予各自的"面法线"，配合美术绘制的法线贴图与片段着色器中的朗伯光照模型，验证"一个光源即可让 2D 精灵呈现明暗体积感"的可行性；编写最小可运行的顶点与片段着色器，评估其在引擎中的扩展空间。

**五、性能基准与正确性验证**。通过自行编写的 cache miss 实测程序量化 SparseSet 双数组寻址在不同访问模式下的延迟差异；通过 false sharing 对照实验直观展示 AoS、padded、SoA 三种布局在多线程写入下的性能差距；使用 GoogleTest 编写 70 余个针对 ECS 核心的单元测试，确保 SparseSet 增删边界、Entity 生命周期、View 遍历交集、System 行为确定性的正确性。

需要明确的是，受限于毕业设计的时间窗口，**以下三项工作不在本论文的研究范围之内**，将作为后续工作展开：（1）HD-2D 后处理的完整实现，包括 bloom、tilt-shift 景深、体积光、Z-buffer 修正；（2）面向美术与策划的可视化关卡编辑器；（3）AI 行为子系统，例如行为树或 GOAP。论文第 9 章将这三项分别列入短期、中期、远期的展望，并在章节结构上为它们预留了插入位置，以保证后续工作不需要重排前序章节。

## 1.4 论文组织结构

全文共分九章，组织结构如下：

第 1 章为绪论，阐述课题背景、国内外研究现状、主要研究内容与目标，并交代论文整体组织方式。

第 2 章梳理本课题涉及的相关技术与理论基础，包括 ECS 架构思想、面向数据设计与缓存局部性、Lua 嵌入式脚本与 sol2、raylib 渲染管线，以及 HD-2D 视觉风格综述。

第 3 章给出引擎的总体架构与模块划分，包括分层架构图、模块清单、主循环数据流，并明确为后续可能加入的编辑器、AI 等模块预留的位置。

第 4 章详述 ECS 核心的设计与实现，包括 Entity 句柄布局、EntityPool 环形缓冲、SparseSet 双数组结构、组件 ID 的编译期分配、Registry 的统一接口与签名机制、以及多组件 View 的最小池驱动算法。

第 5 章按子系统逐一介绍：渲染、物理、碰撞、输入、音频与调试 UI，每节聚焦于该系统在 ECS 框架下的设计要点与关键代码。

第 6 章介绍资源管理与脚本子系统，包括 ResourceManager 的纹理 ID 化、Lua 状态初始化与 sol2 绑定、Tiled 地图解析流程、以及数据驱动的对话分支系统。

第 7 章介绍 HD-2D 渲染风格的原理验证，重点说明立式精灵与地面瓦片的法线区分、shader 实现、以及当前实现的局限。

第 8 章给出性能测试与分析，包括 GoogleTest 单元测试覆盖、cache miss 基准、false sharing 对照实验，以及端到端帧率表现。

第 9 章对全文工作进行总结，分析现存不足，并按短期、中期、远期三档展望后续工作。

论文末尾给出参考文献、附录与致谢。
